Must-Remember Key Points

  1. Java 8 (2014) brought functional-style programming to Java: lambdas, functional interfaces, method references, streams, Optional, default methods, new Date/Time API, CompletableFuture.
  2. Lambda = anonymous function; usable wherever a functional interface (one abstract method) is expected. Captured locals must be effectively final.
  3. Streams are lazy, single-use pipelines (source → intermediate → terminal) that don't modify the source and aren't data structures.
  4. Default/static interface methods let interfaces evolve without breaking implementors. Diamond conflicts must be resolved explicitly.
  5. Optional models "maybe absent" return values; prefer orElseGet/map over get().
  6. java.time is immutable and thread-safe, replacing Date/Calendar/SimpleDateFormat.
  7. CompletableFuture gives non-blocking, composable async pipelines.
  8. Know what is not Java 8 (List.of, var, Stream.toList(), takeWhile...).

1Lambda Expressions

DefinitionA lambda expression is a concise, anonymous function: parameters, an arrow, and a body. It provides an implementation of a functional interface without writing an anonymous class, enabling behaviour to be passed as data.
// syntax: (parameters) -> expression   or   (parameters) -> { statements; }
Runnable r = () -> System.out.println("hi");
Comparator<String> c = (a, b) -> a.length() - b.length();
Function<Integer, Integer> square = x -> x * x;       // single param: no parentheses needed
BinaryOperator<Integer> add = (a, b) -> { return a + b; };

// before Java 8
Collections.sort(list, new Comparator<String>() {
    public int compare(String a, String b) { return a.compareTo(b); }
});
// Java 8
list.sort((a, b) -> a.compareTo(b));      // or list.sort(Comparator.naturalOrder())
  • Target typing: the compiler infers the lambda's type from context (the expected functional interface), so parameter types are usually omitted.
  • Captured variables (locals from the enclosing scope) must be final or effectively final (never reassigned). Instance/static fields can be modified.
  • Benefits: less boilerplate, readable code, enables streams and functional APIs, supports lazy/deferred execution.
LambdaAnonymous inner class
thisThe enclosing instanceThe anonymous object itself
TargetFunctional interfaces onlyAny interface or class
State/fieldsNo own fieldsCan have fields and multiple methods

Pitfall 
int count = 0;
list.forEach(x -> count++);        // compile error: count must be effectively final
// fix: AtomicInteger, a one-element array, or a stream reduction (count())
Follow-up Why must captured locals be effectively final?
Locals live on the stack of the defining thread; a lambda may run later or on another thread, so the value is copied. Allowing mutation would make the copy and original diverge and create thread-safety problems.
Follow-up What does this mean inside a lambda?
The enclosing class instance (lambdas don't introduce a new this), unlike anonymous classes.
Follow-up How are lambdas implemented?
The compiler emits an invokedynamic call; at runtime the JVM (via LambdaMetafactory) generates the implementing class lazily, which is lighter than compiling an inner class per lambda.

2Functional Interfaces

DefinitionA functional interface has exactly one abstract method (SAM) and can be implemented by a lambda or method reference. It may still have any number of default, static methods and methods inherited from Object (e.g. equals).
@FunctionalInterface                    // optional; compiler verifies a single abstract method
interface Validator<T> {
    boolean validate(T t);
    default Validator<T> and(Validator<T> o) { return x -> validate(x) && o.validate(x); }
}
Validator<String> notEmpty = s -> !s.isEmpty();

UnaryOperator<T>T apply(T)Function<T,T>String::trim

Extra 
Predicate<String> p = s -> s.length() > 3;
p.and(s -> s.startsWith("a")).or(s -> s.isEmpty()).negate();     // composition

Function<Integer,Integer> times2 = x -> x * 2, plus3 = x -> x + 3;
times2.andThen(plus3).apply(5);   // 13  (times2 first, then plus3)
times2.compose(plus3).apply(5);   // 16  (plus3 first, then times2)
Function.identity();              // x -> x
  • Primitive specialisations avoid boxing: IntPredicate, IntFunction, ToIntFunction, IntSupplier, IntUnaryOperator, BiConsumer, BiPredicate...
  • Older functional interfaces: Runnable, Callable, Comparator.
  • Comparator has equals declared but it comes from Object, so it still counts as functional.
Follow-up Can a functional interface extend another interface?
Yes, as long as the total number of abstract methods stays one (inherited abstract methods count).
Follow-up andThen vs compose?
f.andThen(g) = g(f(x)); f.compose(g) = f(g(x)).
Follow-up Why primitive specialisations like IntFunction?
To avoid autoboxing overhead in hot paths.

When the lambda adds logic or arguments, or the reference is ambiguous/less readable than the lambda.
Follow-up String::compareTo as a Comparator<String>: how does it fit?
It's the "arbitrary object" kind: (a, b) -> a.compareTo(b). The first argument becomes the receiver.

4Default & Static Methods in Interfaces

DefinitionSince Java 8, interfaces can contain default methods (instance methods with a body, inherited by implementors) and static methods (utility methods on the interface). The goal is backward-compatible interface evolution.
interface Vehicle {
    default String horn() { return "beep"; }          // inherited, overridable
    static Vehicle of(String n) { return () -> n; }    // call as Vehicle.of(...)
    String name();
}
// why: Collection.stream(), List.sort(), Iterable.forEach(), Map.getOrDefault() were added without breaking all existing implementations

Diamond problem rules:

  1. Class wins: a method from a class/superclass beats any interface default.
  2. More specific interface wins (sub-interface overrides super-interface default).
  3. Otherwise compile error: you must override and may call A.super.hello().
class C implements A, B {                // both A and B define default hello()
    public void hello() { A.super.hello(); }   // explicit choice
}
Extra
  • Static interface methods aren't inherited by implementing classes and can't be called through an instance.
  • Default methods can't override Object methods (equals, hashCode, toString).
  • Abstract class vs interface (still different): interfaces have no instance state or constructors, and a class can implement many interfaces. private interface methods arrived in Java 9.
Follow-up Why were default methods introduced?
To add methods like stream() and forEach() to existing interfaces (Collection, Iterable) without breaking every implementation.
Follow-up Is an abstract class now unnecessary?
No. Abstract classes hold state, constructors and non-public members; interfaces can't.

5Stream API

DefinitionA Stream is a sequence of elements supporting declarative, pipelined aggregate operations (filter, map, reduce...). It is not a data structure: it doesn't store data or modify its source, is lazy, and can be consumed only once. It uses internal iteration.
Source→Intermediate ops (lazy, return Stream)→Terminal op (triggers execution)
List<String> result = employees.stream()                     // source
    .filter(e -> e.getSalary() > 50_000)                    // intermediate
    .map(Employee::getName)                                 // intermediate
    .sorted()                                               // intermediate (stateful)
    .collect(Collectors.toList());                          // terminal
Intermediate (lazy)Terminal (eager)
filter, map, flatMap, distinct, sorted, peek, limit, skip, mapToInt/Long/Double, boxed forEach, collect, reduce, count, min, max, anyMatch, allMatch, noneMatch, findFirst, findAny, toArray, sum/average (primitive streams)
Extra 
// creating streams
list.stream();  Arrays.stream(arr);  Stream.of(1, 2, 3);
Stream.iterate(1, n -> n * 2).limit(10);       // infinite → needs limit
Stream.generate(Math::random).limit(5);
IntStream.range(0, 5);  IntStream.rangeClosed(1, 5);    // 0..4  and  1..5
Files.lines(Paths.get("f.txt"));                          // close it (try-with-resources)

// laziness: nothing prints until the terminal op; elements flow one by one through the whole pipeline
Stream.of("a", "bb", "ccc")
      .filter(s -> { System.out.println("filter " + s); return s.length() > 1; })
      .map(s -> { System.out.println("map " + s); return s.toUpperCase(); })
      .findFirst();       // prints: filter a, filter bb, map bb  (short-circuits)
  • Stateless ops (filter, map) vs stateful (sorted, distinct, which need all/many elements). Short-circuiting: limit, findFirst, anyMatch.
  • map: 1 → 1. flatMap: 1 → many, flattened. reduce(identity, op) returns a value; reduce(op) returns an Optional.
  • Primitive streams (IntStream...) avoid boxing and offer sum(), average(), summaryStatistics().
List<String> flat = listOfLists.stream().flatMap(List::stream).collect(toList());
int total = nums.stream().mapToInt(Integer::intValue).sum();
int sum2 = nums.stream().reduce(0, Integer::sum);
IntSummaryStatistics st = nums.stream().mapToInt(i -> i).summaryStatistics();   // min, max, avg, sum, count
CollectionStream
Stores dataYesNo (view of a source)
ReusableYesNo: single use

Pitfalls
  • Reusing a stream: IllegalStateException: stream has already been operated upon or closed.
  • Avoid side effects and mutating the source or external state inside the pipeline (breaks laziness/parallelism; may throw ConcurrentModificationException).
  • peek() is for debugging only. A stream with no terminal operation does nothing.
  • sorted() on non-Comparable elements → ClassCastException. distinct() relies on equals/hashCode.
  • Stream.toList() is Java 16, not 8; in Java 8 use collect(Collectors.toList()).
Follow-up map vs flatMap: when do you need flatMap?
When each element maps to a collection/stream and you want a single flattened stream (e.g. a list of orders → all their items).
Follow-up What does "lazy" mean for streams?
Intermediate operations only build the pipeline; work happens when a terminal operation runs, element by element, which enables short-circuiting and loop fusion.
Follow-up findFirst vs findAny?
findFirst respects encounter order; findAny may return any element, which can be faster on parallel streams.
Follow-up forEach vs forEachOrdered? count() vs collect(counting())?
forEachOrdered keeps encounter order even in parallel. count() is a simple terminal op; counting() is a collector useful as a downstream (e.g. inside groupingBy).

6Collectors

DefinitionA Collector is a mutable reduction strategy used by collect() to gather stream elements into a collection, map, string or summary result. The Collectors class provides ready-made ones.
import static java.util.stream.Collectors.*;

List<String> l = stream.collect(toList());            Set<String> s = stream.collect(toSet());
String csv = names.stream().collect(joining(", ", "[", "]"));      // [a, b, c]

Map<String, List<Employee>> byDept = emps.stream().collect(groupingBy(Employee::getDept));
Map<String, Long>           count  = emps.stream().collect(groupingBy(Employee::getDept, counting()));
Map<String, Double>         avgSal = emps.stream().collect(groupingBy(Employee::getDept, averagingDouble(Employee::getSalary)));
Map<String, List<String>>   names  = emps.stream().collect(groupingBy(Employee::getDept, mapping(Employee::getName, toList())));
Map<Boolean, List<Employee>> part  = emps.stream().collect(partitioningBy(e -> e.getSalary() > 50_000));

Map<Long, Employee> byId = emps.stream().collect(toMap(Employee::getId, Function.identity()));
Map<String, Employee> safe = emps.stream().collect(toMap(Employee::getDept, e -> e, (a, b) -> a)); // merge fn for duplicates

Map<String, Optional<Employee>> top = emps.stream().collect(groupingBy(Employee::getDept,
        maxBy(Comparator.comparingDouble(Employee::getSalary))));
List<String> unmod = stream.collect(collectingAndThen(toList(), Collections::unmodifiableList));
Pitfalls
  • toMap with duplicate keys throws IllegalStateException; supply a merge function. toMap with a null value throws NPE.
  • groupingBy returns a HashMap; pass a supplier for ordering: groupingBy(f, TreeMap::new, toList()) or LinkedHashMap::new.
  • partitioningBy always has both true and false keys (possibly empty lists); groupingBy only has keys that occur.
  • Collectors.teeing is Java 12, not 8.
Follow-up groupingBy vs partitioningBy?
groupingBy: any classifier → Map<K, List>. partitioningBy: boolean predicate → exactly two groups.
Follow-up Group employees by department and get the highest salary per department.
groupingBy(dept, maxBy(comparingDouble(Employee::getSalary))), optionally unwrapped with collectingAndThen(maxBy(...), Optional::get).

7Classic Stream Coding Problems

DefinitionInterviewers love small data-processing tasks. Practise these until the patterns are automatic.
// 1. Second highest salary
Optional<Double> second = emps.stream().map(Employee::getSalary)
    .distinct().sorted(Comparator.reverseOrder()).skip(1).findFirst();

// 2. Word frequency
Map<String, Long> freq = Arrays.stream(text.split("\\s+"))
    .collect(groupingBy(Function.identity(), counting()));

// 3. Find duplicates
Set<Integer> seen = new HashSet<>();
Set<Integer> dups = nums.stream().filter(n -> !seen.add(n)).collect(toSet());

// 4. First non-repeated character
Character c = s.chars().mapToObj(ch -> (char) ch)
    .collect(groupingBy(Function.identity(), LinkedHashMap::new, counting()))
    .entrySet().stream().filter(e -> e.getValue() == 1).map(Map.Entry::getKey).findFirst().orElse(null);

// 5. Sort a map by value (descending)
map.entrySet().stream().sorted(Map.Entry.<String,Integer>comparingByValue().reversed())
   .collect(toMap(Map.Entry::getKey, Map.Entry::getValue, (a, b) -> a, LinkedHashMap::new));

// 6. Sort by multiple fields
emps.sort(Comparator.comparing(Employee::getDept).thenComparing(Employee::getSalary, Comparator.reverseOrder()));

// 7. Even numbers squared, summed
int r = IntStream.rangeClosed(1, 10).filter(n -> n % 2 == 0).map(n -> n * n).sum();

// 8. Check palindrome
boolean pal = IntStream.range(0, s.length() / 2).allMatch(i -> s.charAt(i) == s.charAt(s.length() - 1 - i));

// 9. Join non-null, non-empty strings
String out = list.stream().filter(Objects::nonNull).filter(x -> !x.isEmpty()).collect(joining(","));

// 10. Max / min by field
Employee top = emps.stream().max(Comparator.comparingDouble(Employee::getSalary)).orElseThrow(NoSuchElementException::new);
Say out loud: state the pipeline in words first ("filter, map, then collect by key"), mention edge cases (empty list, nulls, duplicates), and mention complexity (sorting is O(n log n)).

8Parallel Streams

DefinitionA parallel stream splits the source into chunks processed concurrently on the common ForkJoinPool and then combines the results. Created with parallelStream() or stream().parallel().
long count = bigList.parallelStream().filter(this::expensiveCheck).count();
  • Good for: large data sets, CPU-bound, stateless, independent operations, easily splittable sources (ArrayList, arrays, ranges).
  • Bad for: small data, blocking I/O, order-dependent logic, shared mutable state, poorly splittable sources (LinkedList, iterate).
  • All parallel streams share the common pool (size ≈ cores - 1): one slow/blocking task can starve others.
Pitfalls 
List<Integer> out = new ArrayList<>();
nums.parallelStream().forEach(out::add);     // RACE CONDITION: ArrayList isn't thread-safe
// fix: collect(toList()), or a concurrent collection
  • Always measure: parallelism has overhead and often isn't faster.
  • forEach doesn't preserve order in parallel; use forEachOrdered. reduce needs an associative operation and a proper identity.
Follow-up What thread pool do parallel streams use? Can you change it?
The common ForkJoinPool (-Djava.util.concurrent.ForkJoinPool.common.parallelism); a custom pool is possible by submitting the stream task to your own ForkJoinPool, though it's a workaround.
Follow-up When would you not use a parallel stream in a web service?
When tasks block (I/O, DB) or request threads already provide concurrency; sharing the common pool across requests causes contention.

9Optional

DefinitionOptional<T> is a container that may or may not hold a non-null value. It makes "no result" explicit in a method's return type and reduces NullPointerExceptions.
Optional<User> u = Optional.of(user);              // NPE if user is null
Optional<User> n = Optional.ofNullable(maybeNull);  // empty if null
Optional<User> e = Optional.empty();

String city = repo.findById(id)                     // Optional<User>
    .map(User::getAddress)                          // Optional<Address>  (null-safe)
    .map(Address::getCity)
    .filter(c -> !c.isBlank())                      // isBlank is Java 11; use trim().isEmpty() in 8
    .orElse("Unknown");

repo.findById(id).ifPresent(this::notify);
User x = repo.findById(id).orElseThrow(() -> new NotFoundException(id));
MethodUse
map / flatMapTransform the value (flatMap when the function returns an Optional)
filterKeep only if predicate matches
orElse(x)Default value, evaluated eagerly
orElseGet(supplier)Default computed lazily, only if empty
orElseThrow(supplier)Throw if absent
isPresent / ifPresentCheck / run if present
Pitfalls & best practices
  • orElse(expensive()) always runs expensive(); use orElseGet(() -> expensive()).
  • Don't call get() without checking; prefer orElseThrow/map. Avoid the if (opt.isPresent()) opt.get() pattern.
  • Use as a return type; avoid it for fields, method parameters, collection elements (use empty collections instead). It isn't Serializable.
  • Version traps: ifPresentOrElse, or, stream() are Java 9; orElseThrow() (no-arg) is Java 10; isEmpty() is Java 11.
Follow-up map vs flatMap on Optional?
map wraps the result in an Optional; if your function already returns an Optional, use flatMap to avoid Optional<Optional<T>>.
Follow-up Should a method return Optional<List<T>>?
No; return an empty list instead.

10Date & Time API (java.time)

DefinitionThe java.time package (JSR-310) is a modern date/time API whose classes are immutable and thread-safe, with clear separation of human time (dates/zones) and machine time (Instant).

Problems with the old API: Date/Calendar are mutable and not thread-safe, SimpleDateFormat isn't thread-safe, months are 0-indexed, confusing design, poor time-zone support.

Pitfalls
  • d.plusDays(1); alone does nothing: the result must be assigned (immutability).
  • Use ZonedDateTime/Instant for anything crossing time zones or DST; store timestamps as UTC Instant.
  • yyyy vs YYYY (week-based year) in patterns is a classic bug.
Follow-up Duration vs Period?
Duration: time-based (seconds/nanos). Period: date-based (years/months/days). Adding a Period of one day across DST differs from adding a Duration of 24 hours.
Follow-up Why is DateTimeFormatter better than SimpleDateFormat?
It's immutable and thread-safe, so it can be a shared constant.
Follow-up What does LocalDateTime lack?
A time zone/offset, so it doesn't identify a single instant; combine with ZoneId to get a ZonedDateTime.

11CompletableFuture

DefinitionCompletableFuture<T> implements Future and CompletionStage, representing an asynchronous computation you can chain, combine and complete manually, without blocking.

Why not plain Future? get() blocks, no callbacks, no chaining/combining, no built-in exception handling.

CompletableFuture<User>  u = CompletableFuture.supplyAsync(() -> userService.find(id), executor);
CompletableFuture<Order> o = CompletableFuture.supplyAsync(() -> orderService.find(id), executor);

CompletableFuture<String> result = u
    .thenCombine(o, (user, order) -> user.getName() + ": " + order.getTotal())   // combine two independent
    .thenApply(String::toUpperCase)                                              // transform (like map)
    .exceptionally(ex -> "fallback");                                            // error recovery

CompletableFuture.allOf(u, o).join();           // wait for all
CompletableFuture.anyOf(u, o);                  // first to finish
u.thenCompose(user -> fetchOrders(user));       // dependent async step (like flatMap)
MethodPurpose
supplyAsync / runAsyncStart async task (with / without result)
thenApply / thenAccept / thenRunTransform / consume / run after completion
thenComposeChain another CompletableFuture (flatMap)
thenCombineCombine two independent futures
exceptionally / handle / whenCompleteError handling (handle sees result and error)
allOf / anyOfWait for all / any
join vs getjoin throws unchecked CompletionException; get throws checked exceptions
Pitfalls
  • Without an executor, async tasks run on the common ForkJoinPool. Pass your own executor for blocking I/O.
  • Exceptions are wrapped in CompletionException; unhandled failures stay silent until you join()/get().
  • orTimeout/completeOnTimeout are Java 9.
  • Calling join() immediately defeats the purpose; compose first, block once at the edge.
Follow-up thenApply vs thenCompose?
thenApply: function returns a plain value (map). thenCompose: function returns another CompletableFuture (flatMap), avoiding nested futures.
Follow-up Call 3 microservices in parallel and merge results?
Start three supplyAsync calls on a dedicated executor, then allOf(...).thenApply(v -> merge(f1.join(), f2.join(), f3.join())) with exceptionally fallbacks and timeouts.
Follow-up Difference between handle and exceptionally?
exceptionally only runs on failure and returns a fallback; handle runs always with (result, error) and can transform either.

12Other Java 8 Additions

DefinitionBeyond the headline features, Java 8 added many small APIs that appear in everyday code and interviews.
// Iterable / Collection / List

  • Repeating annotations (@Repeatable) and type annotations (@NonNull on types).
  • Concurrency: CompletableFuture, StampedLock (optimistic reads), LongAdder/LongAccumulator (low-contention counters), new ConcurrentHashMap bulk methods (forEach, reduce, search, compute) and its reworked internals (CAS + per-bucket locking, no segments).
  • JVM: PermGen removed → class metadata moves to Metaspace (native memory). HashMap buckets can convert to trees on heavy collisions.

Follow-up How do you count word frequency using Map.merge?
for (String w : words) map.merge(w, 1, Integer::sum); inserts 1 or adds to the existing count atomically in the map's own logic.
Follow-up What changed in HashMap in Java 8?
Collision chains with 8+ nodes (and capacity ≥ 64) convert to balanced trees, improving worst-case lookup from O(n) to O(log n).
Follow-up What replaced PermGen and why?
Metaspace: class metadata lives in native memory that grows dynamically (bounded by -XX:MaxMetaspaceSize), avoiding fixed PermGen sizing errors.

🎯 Tricky & Concept Questions (Recruiter Mode)

Answer out loud first, then tap to check.

Lambda vs anonymous inner class: key differences?
Lambda: functional interfaces only, this = enclosing instance, no own state, implemented via invokedynamic. Anonymous class: any type, has its own this, fields and a separate class file.
Is this a valid functional interface? interface X { void a(); boolean equals(Object o); }
Yes. equals is an Object method, so it doesn't count as an abstract method.
What does this print? Stream.of(1,2,3).peek(System.out::println);
Nothing: no terminal operation, so the pipeline never runs.
What happens if you reuse a stream after a terminal operation?
IllegalStateException (stream already operated upon or closed). Create a new stream from the source.
Can you break or continue inside forEach?
No (it's a lambda; return only skips the current element). Use a regular loop, anyMatch/findFirst for short-circuiting, or takeWhile (Java 9).
Does a stream modify the original collection?
No. Operations produce new results; the source is untouched (unless you mutate it via side effects, which you shouldn't).
reduce(0, Integer::sum) vs mapToInt(...).sum()?
Both sum; the primitive stream avoids boxing and is usually faster and clearer. The reduce form with an identity returns a value; without identity returns an Optional (empty stream).
What if Stream.iterate(1, n -> n + 1) has no limit?
It's infinite and a terminal op like forEach/collect will run forever (or until memory is exhausted). Add limit or a short-circuiting op.
Can sorted() be short-circuited?
No, it's stateful and must see all elements before emitting; elements after it can still short-circuit (e.g. sorted().findFirst() still sorts everything).
Output? IntStream.range(1, 5).sum() vs rangeClosed(1, 5).sum()
10 (1+2+3+4) and 15 (1+...+5).
What happens with Optional.of(null)? Optional.ofNullable(null).get()?
of(null) → NullPointerException. ofNullable(null) gives an empty Optional; get() then throws NoSuchElementException.
Two interfaces with the same default method: how to resolve?
Override the method in your class; optionally delegate with InterfaceName.super.method(). A class method always wins over interface defaults.
Can an interface's static method be called via an implementing class instance?
No. Static interface methods are called only as InterfaceName.method().
Is parallel stream always faster? What can go wrong?
No. Overhead, shared mutable state (races), blocking tasks in the common pool, and ordering assumptions can make it slower or wrong. Measure first.
Convert a List<Employee> to a Map<Integer, Employee> safely.
toMap(Employee::getId, Function.identity(), (a, b) -> a) handles duplicate keys; avoid null values.
Is Java a functional language now?
No, it stays object-oriented but supports functional style (lambdas, higher-order functions, immutability helpers). Streams shift code from "how" (loops) to "what" (declarative).
Stream pipeline vs a for loop: when prefer the loop?
For tiny collections, hot performance-critical code, complex control flow (break/continue, checked exceptions, mutation), or when debugging readability suffers.
