1Polymorphism

DefinitionPolymorphism means "many forms": code written against a parent type or interface behaves differently depending on the actual object it receives (runtime), or on the arguments passed (compile-time).
  • Compile-time (static): method overloading; the compiler picks the method from the reference type and argument types.
  • Runtime (dynamic): method overriding with dynamic method dispatch; the JVM picks the implementation from the actual object type.
  • In Spring Boot: interfaces + dependency injection, strategy pattern, service abstractions → loose coupling and extensibility.
interface PaymentStrategy { void pay(double amt); }
class CardPayment implements PaymentStrategy { public void pay(double a){ /* card */ } }
class UpiPayment  implements PaymentStrategy { public void pay(double a){ /* upi  */ } }

PaymentStrategy p = new UpiPayment();
p.pay(100);   // UpiPayment.pay runs: decided at runtime
Added 
class A { String name="A"; static String s(){return "A";} String who(){return "A";} }
class B extends A { String name="B"; static String s(){return "B";} String who(){return "B";} }
A a = new B();
a.who();   // "B"  runtime dispatch
a.name;    // "A"  fields are hidden, not overridden
a.s();     // "A"  static methods are hidden, not overridden

void p(Object o){}  void p(String s){}
Object o = "x";  p(o);   // Object version (compile-time type)
p(null);                 // String version (most specific)
  • Override rules: same signature; covariant return allowed; access can't be narrower; checked exceptions can't be broader; no overriding final/static/private.
  • Not polymorphic: fields, static methods, private methods, constructors.
Follow-up Overloading vs overriding: key differences?
Overloading: same name, different parameters, resolved at compile time. Overriding: subclass, same signature, resolved at runtime, needs inheritance.
Follow-up p(String) and p(Integer): what does p(null) do?
Compile error: ambiguous call. With p(Object) and p(String) it picks String (most specific).
Follow-up A constructor calls an overridable method. What's the risk?
The subclass override runs before subclass fields are initialised, so it sees defaults (null/0).
Follow-up How does the JVM do dynamic dispatch internally?
Each class has a virtual method table; invokevirtual looks up the method for the object's actual class at runtime.

2Abstract Class

DefinitionAn abstract class is a class declared abstract that cannot be instantiated. It acts as a partially built base class: it provides shared fields and code, and can declare abstract methods that every concrete subclass must implement.
  • Can contain constructors, instance variables, concrete methods and abstract methods.
  • Use when implementations share state and behaviour but need specialisation: template method, base services, workflow frameworks, payment and notification frameworks.
abstract class Payment {
    public final void process() { validate(); execute(); notifyUser(); }  // template method
    protected void validate() { /* common */ }
    protected abstract void execute();                                    // subclass specialises
    private void notifyUser() { /* common */ }
}
class CardPayment extends Payment { protected void execute() { /* charge card */ } }

Follow-up Can an abstract class have a constructor? Why?
Yes. It runs when a subclass is created (via super()) to initialise the shared fields.
Follow-up Can it have no abstract methods?
Yes; it just prevents direct instantiation. Illegal combos: abstract with final, private or static.
Follow-up Java 8 added default methods. Is the abstract class now obsolete?
No. Interfaces still can't hold instance state or constructors. Choose an abstract class when subclasses share state.
Follow-up Two interfaces have the same default hello(). What happens?
Compile error until you override it; choose one with A.super.hello().

3Java Memory Model (JMM)

DefinitionThe JMM is the part of the Java specification that defines when a write by one thread is guaranteed to be visible to another thread, and which instruction reorderings are allowed. It's what makes multi-threaded code predictable.
  • Specifies: visibility of writes, ordering of reads/writes, synchronization rules.
  • Each thread has working memory (fast, cache-like); shared variables live in main memory. Changes must be synchronised out; other threads must refresh.
  • Happens-before: if A happens-before B, A's results are visible to B and A is ordered before B.
  • Rules: program order, monitor unlock → lock, volatile write → read, Thread.start(), Thread.join(), transitivity.
  • volatile = visibility + ordering, not atomicity. synchronized = visibility + atomicity.
  • Without guarantees: stale values and reordered operations. Memory barriers enforce ordering at the CPU level.
Nuance "Working memory = CPU cache" is a simplification. The JMM is an abstraction over registers, caches and compiler/CPU reordering, not a literal hardware model.
Added: three concurrency problems Atomicity (compound ops), Visibility (stale reads), Ordering (reordering). 
class Worker {
    private volatile boolean running = true;     // without volatile, the loop may never stop
    void loop() { while (running) { /* work */ } }
    void stop() { running = false; }
}

class Singleton {                                // double-checked locking
    private static volatile Singleton inst;
    static Singleton get() {
        if (inst == null) {
            synchronized (Singleton.class) { if (inst == null) inst = new Singleton(); }
        }
        return inst;
    }
}
  • Why volatile in DCL: new = allocate → construct → assign; reordering can publish a non-null, half-built object.
  • Alternatives: static holder idiom, enum singleton. Safe publication: static initialiser, volatile/final field, or lock.
Follow-up volatile int count; count++ from 10 threads: correct?
No. count++ is read-modify-write, not atomic. Use AtomicInteger or synchronized.
Follow-up Is synchronized only about mutual exclusion?
No, it also gives visibility: unlock → lock is a happens-before edge, so the next thread sees all prior writes.
Follow-up Are long writes atomic?
The spec doesn't guarantee it for non-volatile 64-bit values (two 32-bit writes possible). Use volatile if shared; modern 64-bit JVMs usually behave atomically.
Follow-up What is instruction reordering and why is it allowed?
Compilers/CPUs reorder instructions for speed when single-thread results don't change. In multi-threaded code this can expose inconsistent states, hence happens-before rules.

4ClassLoader

DefinitionA ClassLoader is the JVM component that finds a class's bytecode (.class data) and turns it into a Class object in memory, on demand at runtime.
  • Responsibilities: find/load .class files, convert bytecode to classes, load each class once (per loader), manage namespaces.
1. Loading→2. Linking: verify · prepare · resolve→3. Initialization
  • Verification: bytecode valid. Preparation: memory for statics (default values). Resolution: symbolic → direct references. Initialization: run static initialisers and assign static values.
Bootstrap→Platform (was Extension)→Application→Custom

Parent delegation: a loader asks its parent first and loads the class itself only if the parent can't. This protects core classes (nobody can replace java.lang.String) and keeps them unique.

Correction Since Java 9 the Extension ClassLoader was replaced by the Platform ClassLoader. Your 3-tier list is the Java 8 view.
Added 
String.class.getClassLoader();   // null → Bootstrap
MyApp.class.getClassLoader();    // AppClassLoader

class P { static { print("P static"); } { print("P instance"); } P(){ print("P ctor"); } }
class C extends P { static { print("C static"); } { print("C instance"); } C(){ print("C ctor"); } }
new C();  // P static, C static, P instance, P ctor, C instance, C ctor
  • Class identity = fully qualified name + loader. Same class from two loaders = two different types.
  • Loading is lazy. Initialization triggers: new, static method call, non-constant static field access.
  • Class.forName(n) loads and initialises; loadClass(n) doesn't initialise.
  • Use cases: Tomcat per-webapp isolation and hot redeploy, plugins, OSGi. Leaked loaders → Metaspace OOM.
Follow-up ClassNotFoundException vs NoClassDefFoundError?
ClassNotFoundException: checked; dynamic load by name failed. NoClassDefFoundError: class was there at compile time but missing at runtime, or its static init failed earlier.
Follow-up Why can't you ship your own java.lang.String?
Parent delegation: Bootstrap supplies the real one first.
Follow-up Why would you write a custom ClassLoader?
Load classes from non-standard sources (network, DB, encrypted files), isolate modules/plugins, or hot-reload code.

5Memory Leak in Java

DefinitionA memory leak is when objects are no longer needed but still referenced, so the garbage collector can't reclaim them. Memory use grows until performance degrades or OutOfMemoryError occurs.
  • Result: rising memory, OOM, slowdown, crashes.
  • Causes: unclosed resources (most common), static collections, listeners/callbacks not removed, ThreadLocals not removed, inner classes holding the outer reference, mutable static fields.
  • Detect: heap dump, VisualVM, JConsole.
Added 
static final List<byte[]> CACHE = new ArrayList<>();      // grows forever → leak
try (Connection c = ds.getConnection()) { ... }            // fix: always close resources
try { tl.set(ctx); work(); } finally { tl.remove(); }      // ThreadLocal in thread pools

class Key { int id; }                                      // no equals/hashCode
map.put(new Key(1), v); map.get(new Key(1));               // null → duplicates pile up
  • Capture: -XX:+HeapDumpOnOutOfMemoryError or jmap -dump:live,format=b,file=heap.hprof <pid>; analyse with Eclipse MAT (Leak Suspects, Dominator Tree) or JFR.
  • Symptom: heap after each Full GC keeps rising.
  • Fixes: bounded caches (Caffeine, LRU LinkedHashMap), WeakHashMap, deregister listeners, static nested classes.
Follow-up Java has GC. How can it still leak?
GC frees unreachable objects only. A leak is reachable but useless.
Follow-up Does every OOM mean a leak? How do you tell?
No: could be an undersized heap or real load. Check whether post-GC heap trends up over time, and which OOM type: heap space, Metaspace, direct memory, or native thread creation.
Follow-up Walk me through diagnosing a production leak.
Confirm the trend (GC logs/metrics) → take heap dumps (or enable on-OOM) → open in MAT → find the dominator holding memory → trace the GC-root path → fix the reference → verify under load.
Follow-up How can an inner class leak?
Non-static inner classes hold an implicit reference to the outer instance; a long-lived inner object keeps the whole outer object alive.

6Garbage Collector

DefinitionGarbage collection is the JVM's automatic memory management: it finds objects that can no longer be reached from GC roots (stack variables, static fields, active threads, JNI refs) and reclaims their memory.
Mark reachable→Sweep unmarked→Compact (optional)
CollectorFlagTraits
Serial-XX:+UseSerialGCSingle thread; small heaps, single core
Parallel-XX:+UseParallelGCThroughput; Java 8 default; batch
CMS-XX:+UseConcMarkSweepGCLow pause; removed in Java 14
G1-XX:+UseG1GCRegion-based, predictable pauses; default Java 9+
ZGC-XX:+UseZGCUltra-low latency, very large heaps
Shenandoah-XX:+UseShenandoahGCUltra-low latency, similar to ZGC
Corrections
  • CMS: deprecated in 9, removed in 14.
  • ZGC: experimental in 11, production in 15; pauses now typically sub-millisecond; generational ZGC in 21.
  • Shenandoah: production since 15, but in OpenJDK builds, not Oracle JDK.
Added
  • Choosing: batch throughput → Parallel; general services → G1; strict latency / huge heaps → ZGC or Shenandoah.
  • Heap = Young (Eden + S0/S1, copying collector) + Old (mark-sweep-compact). Minor GC: young. Full GC: whole heap, most expensive.
  • Flags: -Xms/-Xmx, -XX:MaxGCPauseMillis=200 (G1), -Xlog:gc* (Java 9+).
Follow-up Service has latency spikes. How do you investigate GC?
Enable GC logging, look for long pauses/Full GCs, check allocation rate and heap sizing, then consider G1 tuning or ZGC.
Follow-up What is stop-the-world?
A phase where all application threads are paused so GC can work safely. Low-latency collectors minimise it by working concurrently.
Follow-up Why generational GC? What is promotion?
Most objects die young, so collecting the small young gen often is cheap. Objects surviving several minor GCs are promoted to old gen.
Follow-up Strong, soft, weak, phantom references?
Strong: never collected while reachable. Soft: collected under memory pressure (caches). Weak: collected at next GC (WeakHashMap). Phantom: for post-collection cleanup.
Follow-up Does calling System.gc() force collection?
It's only a request and often harmful. Avoid it.

7ReentrantLock

DefinitionReentrantLock is a mutual-exclusion lock from java.util.concurrent.locks with explicit lock()/unlock(). "Reentrant" means the thread that owns the lock can acquire it again without blocking.
synchronizedReentrantLock
Acquire/releaseImplicit, automaticManual
Timeout / tryLockNoYes
InterruptibleNolockInterruptibly()
FairnessNoOptional
ConditionsSingle wait-setMultiple Conditions
StyleSimplerMore flexible, more control
Added 
private final ReentrantLock lock = new ReentrantLock();
void update() {
    lock.lock();
    try { /* critical section */ } finally { lock.unlock(); }   // ALWAYS in finally
}
if (lock.tryLock(2, TimeUnit.SECONDS)) {                         // avoids waiting forever
    try { /* work */ } finally { lock.unlock(); }
}
  • synchronized is also reentrant; reentrancy isn't the difference.
  • Fair mode (new ReentrantLock(true)) reduces starvation but lowers throughput.
  • Condition.await() belongs in a while loop (spurious wakeups).
Follow-up Forgot unlock(), or unlocked without owning it?
Forgetting blocks every other thread forever. Unlocking without ownership throws IllegalMonitorStateException.
Follow-up When would you pick ReentrantLock over synchronized?
When you need tryLock/timeouts, interruptible waits, fairness, multiple conditions, or lock/unlock across different methods. Otherwise prefer synchronized for simplicity.
Follow-up How do you prevent deadlocks?
Consistent lock ordering, tryLock with timeout, short critical sections, no calls to unknown code while holding a lock.

8ReadWriteLock

DefinitionA ReadWriteLock is a pair of locks: a shared read lock (many threads at once) and an exclusive write lock (one thread, no readers). The standard implementation is ReentrantReadWriteLock.
  • Use case: cache with many readers and few writers. Readers don't block each other; the writer waits for readers, then gets exclusive access.
  • Without it, 100 readers take turns (bottleneck); with it, they read simultaneously.
private final ReadWriteLock rw = new ReentrantReadWriteLock();
V get(K k)         { rw.readLock().lock();  try { return map.get(k); } finally { rw.readLock().unlock(); } }
void put(K k, V v) { rw.writeLock().lock(); try { map.put(k, v); }     finally { rw.writeLock().unlock(); } }
Added
  • Downgrade (write → read) is allowed; upgrade (read → write) is not: it deadlocks.
  • Non-fair mode can starve writers. StampedLock adds optimistic reads for higher read throughput (not reentrant).
  • Worth it only when reads ≫ writes and read sections aren't trivial; ConcurrentHashMap is often simpler for caches.
Follow-up A thread holding a read lock requests the write lock. What happens?
It waits for all read locks, including its own, to release: self-deadlock.
Follow-up Is ReadWriteLock always faster than a plain lock?
No. It has more overhead, and with frequent writes or tiny critical sections a plain lock or concurrent collection can win.

9ThreadLocal

DefinitionThreadLocal gives each thread its own independent copy of a variable. A value set by one thread is visible only to that thread.
Added 
private static final ThreadLocal<SimpleDateFormat> FMT =
        ThreadLocal.withInitial(() -> new SimpleDateFormat("yyyy-MM-dd"));   // per-thread copy

static final ThreadLocal<String> USER = new ThreadLocal<>();
try { USER.set("alice"); service.run(); }
finally { USER.remove(); }                       // critical in thread pools
  • Internals: each Thread has a ThreadLocalMap; keys are weak refs to the ThreadLocal, values are strong. Pool threads live long, so stale values leak.
  • Real uses: SecurityContextHolder, RequestContextHolder, transaction sync, SLF4J MDC, per-thread non-thread-safe objects.
  • Not propagated to new/executor/@Async threads; InheritableThreadLocal copies only at thread creation. Use a TaskDecorator.
  • Heavy per-thread data is costly with many virtual threads; ScopedValue is a newer alternative.
Follow-up Keys are weak, so why does it still leak?
Only the key is weak. The value stays strongly referenced by the thread's map until remove() or cleanup, and pool threads never die.
Follow-up You store the user in a ThreadLocal and call an @Async method. What breaks?
The async thread has an empty ThreadLocal. Copy context with a TaskDecorator or pass data explicitly.
Follow-up ThreadLocal vs synchronization?
Synchronization shares one object safely; ThreadLocal avoids sharing by giving each thread its own copy.

🎯 More Core Java Concept Questions (Recruiter Mode)

Tap each question, answer out loud first, then check.

OOP & Design

Explain the 4 pillars of OOP with one example each.
Encapsulation: private fields + getters/setters. Abstraction: expose what, hide how (interfaces). Inheritance: reuse via extends. Polymorphism: one type, many behaviours.
Composition vs inheritance: which do you prefer and why?
Prefer composition ("has-a"): looser coupling, swappable at runtime, avoids the fragile-base-class problem. Use inheritance only for true "is-a" with stable base classes.
How do you create an immutable class?
Make the class final, fields private final, no setters, set everything in the constructor, and defensively copy mutable inputs/outputs (e.g. Date, collections). 
public final class Money {
    private final BigDecimal amount;
    private final List<String> tags;
    public Money(BigDecimal a, List<String> t){ this.amount=a; this.tags=List.copyOf(t); }
    public List<String> tags(){ return tags; }        // already immutable
}
Benefits: thread safety, safe map keys, caching. Java 16+ record gives a shallowly immutable data carrier.
Shallow copy vs deep copy? Problem with clone()?
Shallow copies references (both objects share nested objects); deep copies nested objects too. Object.clone() is shallow and awkward (Cloneable marker, checked exception); prefer copy constructors or factory methods.
Are constructors inherited? this() vs super()?
Not inherited. this() calls another constructor in the same class; super() calls the parent constructor. Both must be the first statement. If you define any constructor, the compiler no longer adds the default one.

Collections

How does HashMap work internally?
Array of buckets; index = (n-1) & hash(key); collisions chain as a linked list that becomes a Red-Black tree at 8 nodes (and table ≥ 64); resizes (doubles) when size exceeds capacity × 0.75. equals() finds the exact key within a bucket.
ArrayList vs LinkedList?
ArrayList: dynamic array, O(1) index access, amortised O(1) append, O(n) middle insert/remove. LinkedList: doubly linked, O(1) at ends, O(n) access by index. In practice ArrayList wins most of the time (cache locality).
Comparable vs Comparator?
Comparable: natural order inside the class (compareTo), one ordering. Comparator: external, many orderings (compare). 
people.sort(Comparator.comparing(Person::getAge).thenComparing(Person::getName));
HashSet, LinkedHashMap, TreeMap: how do they differ?
HashSet is backed by a HashMap (elements are keys). LinkedHashMap keeps insertion (or access) order, handy for LRU caches. TreeMap is a Red-Black tree: sorted, O(log n); it uses compareTo/Comparator for equality, not equals.
Fail-fast vs fail-safe iterators?
Fail-fast (ArrayList, HashMap) throw ConcurrentModificationException on structural change (best effort, via modCount). Fail-safe/weakly consistent (CopyOnWriteArrayList snapshot, ConcurrentHashMap) don't throw.

Strings & Types

Why is String immutable? StringBuilder vs StringBuffer?
Enables the string pool, cached hash code, thread safety and security. StringBuilder is fast and not thread-safe; StringBuffer is synchronized. Avoid += in loops. 
String a = "hi", c = new String("hi");
a == c;  a.equals(c);  a == c.intern();   // false, true, true
What is autoboxing and what can go wrong?
Automatic primitive ↔ wrapper conversion. Pitfalls: Integer i = null; int j = i; throws NPE; == on wrappers compares references (cache only for -128..127); boxing in hot loops creates garbage.
Explain the equals()/hashCode() contract.
Equal objects must have equal hash codes (the reverse isn't required). Override both together using the same fields. Mutating those fields after inserting into a hash collection makes the entry unfindable.
What is type erasure in generics?
Generic type info is removed at compile time, so List<String> and List<Integer> are the same class at runtime. Hence no new T(), no List<int>, no instanceof List<String>. PECS: Producer Extends, Consumer Super.

Exceptions

Checked vs unchecked exceptions vs Errors?
Checked (Exception but not RuntimeException): compiler forces handle/declare; for recoverable conditions. Unchecked (RuntimeException): programming errors (NPE, IllegalArgument). Error (OOM, StackOverflow): JVM problems, don't catch.
How does try-with-resources work? Does finally always run?
Resources implementing AutoCloseable close automatically in reverse order; exceptions from close() become suppressed. finally runs unless System.exit() or a JVM crash; a return in finally overrides the try's return.

Java 8+ Features

What is a functional interface? Name the common ones.
An interface with exactly one abstract method (@FunctionalInterface), usable with lambdas. Common: Predicate (T→boolean), Function (T→R), Consumer (T→void), Supplier (()→T), UnaryOperator, BiFunction. Lambdas can only capture effectively final locals.
Stream map vs flatMap? Intermediate vs terminal?
map transforms 1→1; flatMap flattens 1→many. 
List<String> all = lists.stream().flatMap(List::stream).toList();
Map<String, List<Emp>> byDept = emps.stream().collect(Collectors.groupingBy(Emp::dept));
Intermediate ops (filter, map) are lazy; nothing runs until a terminal op (collect, forEach). A stream can be consumed only once.
Optional.orElse vs orElseGet? Where not to use Optional?
orElse(x) always evaluates x; orElseGet(supplier) evaluates lazily. Use Optional as a return type; avoid it for fields, parameters and collections.
Which modern Java features should a 5-year dev know?
var (10), switch expressions (14), text blocks (15), record and pattern-matching instanceof (16), sealed classes (17), virtual threads (21).

Concurrency Basics

Thread lifecycle states?
NEW → RUNNABLE → BLOCKED (waiting for a monitor) / WAITING (wait(), join()) / TIMED_WAITING (sleep, timed waits) → TERMINATED.
wait() vs sleep()?
wait(): on an object, must hold its monitor (inside synchronized), releases the lock, woken by notify; call in a while loop. sleep(): on Thread, keeps locks, just pauses.
What causes a deadlock? How do you detect it?
Four conditions together: mutual exclusion, hold-and-wait, no preemption, circular wait. Break one (e.g. lock ordering). Detect with jstack thread dumps or JVisualVM.
Runnable vs Callable? What is CAS?
Callable returns a value and may throw checked exceptions; Runnable doesn't. CAS (compare-and-swap) is a lock-free atomic update used by Atomic* classes: update only if the current value equals the expected one, else retry. Caveat: the ABA problem (AtomicStampedReference).

JVM Basics

Stack vs heap? StackOverflowError vs OutOfMemoryError?
Stack: per-thread frames with locals and references. Heap: shared, holds objects, managed by GC. StackOverflowError: too-deep recursion (stack size, -Xss). OutOfMemoryError: heap/Metaspace/native exhausted.
What is Metaspace and the JIT compiler?
Metaspace (native memory, replaced PermGen in Java 8) stores class metadata. The JIT compiles hot bytecode to native code at runtime (tiered C1/C2) for speed.
Define it clearly, give an example, state the trade-off, and be ready for the follow-up.
